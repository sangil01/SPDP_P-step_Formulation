## Pick-up / Delivery symmetry breaking as a valid strengthening

### Forward label

In the current forward pricing algorithm, each label is

$$
l = (x, K_l, C_l, T_l, U_l, M_l^{P}, M_l^{D}),
$$

where

- $x=(i,\sigma(i))$ is the current node-state,
- $K_l$ is the current length,
- $C_l$ is the cumulated modified path cost,
- $T_l$ is the cumulated time,
- $U_l$ is the visited physical-node set,
- $M_l^{P}$ is the pick-up ordering memory, (from COR (2022))
- $M_l^{D}$ is the delivery ordering memory. (new idea)

### Pick-up and delivery classes are different

The two symmetry-breaking rules do **not** use the same class definition.

For a pick-up node $p_r$, define the pick-up class as

$$
\kappa^{P}(p_r)
=
(\operatorname{loc}(p_r), \operatorname{landfill}(p_r), \operatorname{type}(p_r)).
$$

For a delivery node $d_r$, define the delivery class as

$$
\kappa^{D}(d_r)
=
(\operatorname{loc}(d_r), \operatorname{type}(d_r)).
$$

Thus:

- $M_l^{P}(c)$ stores the largest request ID of a previously visited pick-up in class $c$,
- $M_l^{D}(c)$ stores the largest request ID of a previously visited delivery in class $c$.

### Forward extension with symmetry-breaking

When extending a label through an arc

$$
e=(x,y),
$$

the extension is allowed only if:

- $T_l+t_e \le T$,
- $\operatorname{loc}(y)\notin U_l$,
- if $y$ is a pick-up node, then

$$
\operatorname{request\_id}(y) > M_l^{P}(\kappa^{P}(y)),
$$

- if $y$ is a delivery node, then

$$
\operatorname{request\_id}(y) > M_l^{D}(\kappa^{D}(y)).
$$

After extension:

- $M_l^{P}$ is updated only when $y$ is a pick-up node,
- $M_l^{D}$ is updated only when $y$ is a delivery node.

Therefore, the current pricing algorithm uses **two distinct ordering restrictions**:

1. pick-up ordering symmetry-breaking,
2. delivery ordering symmetry-breaking.

## Observation from computational experiments

### Root LP bound increased in some instances

In the recent experiments, the **root LP bound increased after activating
delivery ordering symmetry-breaking**.

This should be distinguished from the pick-up symmetry case. The baseline
already follows COR (2022), where pick-up ordering symmetry-breaking is used.
Hence, activating only the pick-up ordering rule does not raise the root LP
bound relative to the baseline. In contrast, the newly added delivery ordering
rule produced a strictly larger root LP bound in some instances.

Representative examples:

- `RecDep_day_A2`
- `RecDep_day_C4`
### Interpretation

This suggests that the additional delivery ordering restriction removes some
fractional p-step columns and yields a stronger LP relaxation.

## Prove valid strengthening

Let

$$
R^p
$$

be the original set of feasible compact p-step columns, and let

$$
R^{p,\mathrm{sym}} \subseteq R^p
$$

be the subset of columns satisfying both:

- pick-up ordering symmetry-breaking, and
- delivery ordering symmetry-breaking.

To prove that the restricted formulation is a **valid strengthening**, it is
sufficient to show that every feasible integer solution of the original master
can still be represented using only columns in

$$
R^{p,\mathrm{sym}}.
$$

Equivalently, for every feasible integer route set of the original SPDP, we
must be able to construct another feasible route set with:

- the same objective value,
- the same physical vehicle movements and state transition,
- and the property that every induced p-step satisfies the two ordering rules.

If this is proved, then:

- the restricted formulation preserves all integer feasible solutions,
- the LP relaxation may become strictly stronger by removing fractional columns,
- and the observed increase in root LP bound is a genuine strengthening effect.

### Pick-up ordering

For a pick-up node $p_r$, define the pick-up symmetry class

$$
\kappa^{P}(p_r)
=
(\operatorname{loc}(p_r), \operatorname{landfill}(p_r), \operatorname{type}(p_r)).
$$

Take any feasible integer route set of the original formulation. Fix one
pick-up class $c$, and let

$$
\mathcal P(c)=\{p_{r_1},\dots,p_{r_k}\}
$$

be the pick-up visits of class $c$ in their visiting order. Let

$$
\hat r_1 < \hat r_2 < \cdots < \hat r_k
$$

be the same request IDs sorted increasingly. Relabel the $t$-th visited node in
$\mathcal P(c)$ as request $\hat r_t$.

This does not change the physical route, cost, time, or state evolution,
because all requests in class $c$ have the same:

- pick-up location,
- landfill destination,
- container type,
- pick-up state transition

$$
N \to F(h,l),
$$

- local service semantics.

The relabeling is a bijection inside class $c$, so the request rows are still
covered exactly once. Repeating this independently for every pick-up class
produces an equivalent feasible integer solution satisfying the pick-up
ordering rule. Hence the pick-up ordering restriction preserves all integer
feasible solutions.

### Delivery ordering

For a delivery node $d_r$, define the delivery symmetry class

$$
\kappa^{D}(d_r)
=
(\operatorname{loc}(d_r), \operatorname{type}(d_r)).
$$

Fix one delivery class $c$, and let

$$
\mathcal D(c)=\{d_{r_1},\dots,d_{r_k}\}
$$

be the delivery visits of class $c$ in their visiting order. Let

$$
\hat r_1 < \hat r_2 < \cdots < \hat r_k
$$

be the same request IDs sorted increasingly. Relabel the $t$-th visited node in
$\mathcal D(c)$ as request $\hat r_t$.

This again does not change the physical route, cost, time, or state evolution,
because all requests in class $c$ have the same:

- delivery location,
- requested type,
- delivery state transition

$$
E(h) \to N,
$$

- local service semantics.

In particular, delivery only consumes an empty container of type $h$, and the
request ID itself does not appear in the delivery state transition. The relabeling is a
bijection inside class $c$, so the delivery rows are still covered exactly
once. Repeating this independently for every delivery class produces an
equivalent feasible integer solution satisfying the delivery ordering rule.
Hence the delivery ordering restriction also preserves all integer feasible
solutions.

### Theorem

The pick-up relabeling changes only pick-up request IDs, while the delivery
relabeling changes only delivery request IDs. Hence the two relabelings can be
applied successively.

Thus every feasible integer route set of the original formulation can be
converted into another feasible integer route set with:

- the same objective value,
- the same physical movements and state evolution,
- both ordering rules satisfied.

Using the same route decomposition, every induced p-step then belongs to

$$
R^{p,\mathrm{sym}}.
$$

Therefore every feasible integer solution of the original master can still be
represented using only columns in $R^{p,\mathrm{sym}}$. Hence the formulation
restricted by pick-up / delivery ordering symmetry is a valid strengthening of
the original p-step master formulation.

### Consequence

The observed increase of the root LP bound in instances such as:

- `RecDep_day_A2`
- `RecDep_day_C4`
