## Pricing complexity

### Decision problem

Consider the decision version of the pricing problem. Fix a start state

$$
u=(s,\sigma_s),
$$

and an integer bound $B$. The question is whether there exists a feasible p-step

$$
r=(e_1,\dots,e_q)\in R^p
$$

starting from $u$ such that $q\le p$, the path is elementary, edge and state
continuity hold along the path, the time bound $t(r)\le T$ is satisfied, the
pick-up / delivery ordering rules are satisfied, and the reduced cost

$$
\bar c_r = C(P_r)+\Phi(u,v,t(r))
$$

is at most $B$, where the terminal state $v=(f,\sigma_f)$ is determined by the
last node-state of $r$.

### NP-hardness when $p$ is part of variable

When $p$ is part of the variable, this problem is NP-hard. The reason is that the
standard ESPPRC decision problem can be embedded as a special case. Start from
any ESPPRC instance with one source, one sink, arc costs $w_e$, a resource
bound $T$, and elementarity. Use the same graph and the same source state in
the current pricing problem, allow only one admissible terminal state

$$
v^*=(f^*,\sigma_{f^*}),
$$

assign every request to a distinct class so that the ordering rules become
vacuous, and choose the dual terms so that

$$
\Phi(u,v,t)=
\begin{cases}
0 & \text{if } v=v^*,\\
M & \text{otherwise,}
\end{cases}
$$

for a sufficiently large constant $M$. Then every feasible p-step ending at
$v^*$ has reduced cost

$$
\bar c_r=\sum_{e\in r} w_e+\text{const},
$$

while every path ending at a different terminal is automatically dominated by
the large penalty $M$. Hence the resulting pricing decision problem is exactly
the original ESPPRC decision problem up to an additive constant. Therefore the
current pricing problem is NP-hard whenever $p$ is not fixed.

### Polynomial solvability for fixed $p$

In contrast, when $p$ is fixed as a constant, the problem is polynomially
solvable by explicit enumeration. Indeed, the number of edge sequences of
length at most $p$ is

$$
O(|E|^p),
$$

and for each candidate sequence all feasibility checks, namely edge/state
continuity, elementarity, time feasibility, pick-up / delivery ordering
feasibility, and reduced-cost evaluation, can be carried out in polynomial
time. Therefore the entire pricing problem is polynomially solvable for fixed
$p$. The complexity classification is thus the usual one for bounded-length
path problems: NP-hard when $p$ is part of the input, but polynomial when $p$
is fixed.

### Algorithmic implication

This complexity statement is independent of the algorithmic fact that the
current pricing problem is not a standard single-sink ESPPRC. Because the
reduced cost has the form

$$
\bar c_r=C(P_r)+\Phi(u,v,t(r)),
$$

the completion value depends on the terminal state $v$, so the pricing problem
is naturally a start-fixed, multi-sink elementary resource-constrained path
problem rather than a fixed-terminal ESPPRC. This distinction does not change
the NP-hard versus fixed-$p$ polynomial classification above, but it does
matter for the design of efficient labeling algorithms.
