# Heuristic algorithm for incumbent solution

목표: duration IP로 구한 fleet-size LB $\hat k_D$를 고정하고 feasible solution을 찾는다. 이를 위해 MILP 대신 Han, Lee & Kim (EJOR, 2026)의 pattern-based ALNS (PALNS)를 SPDP에 맞게 변형해 사용한다.

## 0. Problem description

이 절에서는 SPDP를 PALNS의 작업 단위로 다시 기술한다.

### 0.1 데이터와 작업

- request 집합은 $R$, skip type 집합은 $F$이다. 각 request $r\in R$는 $(\alpha_r,\beta_r,\omega_r,\phi_r)$로 주어지며, 각각 수거지, 처리시설(고정), 배달지, type을 뜻한다. 데이터에서는 $\omega_r=\alpha_r$이다.
- 작업은 다음 세 종류이다.

$$
P_r:\ \alpha_r\text{에서 full skip 수거},\qquad
E_r:\ \beta_r\text{에서 비움},\qquad
D_q:\ \omega_q\text{에 type }\phi_q\text{ 빈 skip 배달}.
$$

- 작업 $o$의 위치를 $\ell(o)$, 서비스 시간을 $s(o)$로 쓴다.

$$
\ell(P_r)=\alpha_r,\quad \ell(E_r)=\beta_r,\quad \ell(D_q)=\omega_q,\qquad
s(P_r)=s^p,\quad s(E_r)=s^e,\quad s(D_q)=s^d.
$$

- 작업 수열 $\pi=(o_1,\dots,o_m)$의 duration과 cost는 아래와 같다. 같은 위치 사이에서는 $t_{uu}=c_{uu}=0$이다. 이동시간 $t$와 이동비용 $c$는 서로 다른 행렬이고, 둘 다 triangle inequality를 만족한다고 가정하지 않는다.

$$
d(\pi)=\sum_{k=1}^{m}s(o_k)+\sum_{k=1}^{m-1}t_{\ell(o_k)\ell(o_{k+1})},\qquad
c(\pi)=\sum_{k=1}^{m-1}c_{\ell(o_k)\ell(o_{k+1})}.
$$

- flexible return이 적용되므로, $E_r$에서 나온 빈 skip은 $\phi_q=\phi_r$인 어떤 $D_q$로도 보낼 수 있다.

### 0.2 Fixed-$K$ incumbent problem

route $\rho$는 작업 수열이다. 작업 $o_k$를 마친 직후의 load를 다음과 같이 정의한다.

$$
L_k(\rho)=\#\{P\in o_{1..k}\}-\#\{D\in o_{1..k}\}.
$$

$K=\hat k_D$로 둔다. 다음 조건을 모두 만족하는 route 집합 $\{\rho_1,\dots,\rho_K\}$를 찾는다.

1. **pickup coverage.** 모든 $r\in R$에 대해 $P_r$과 $E_r$이 정확히 한 번씩 수행된다. 두 작업은 같은 route에서 이루어지며, $P_r$이 $E_r$보다 먼저 온다.
2. **delivery coverage.** 모든 delivery class $q$에 대해 $D_q$가 정확히 $m_q$번 수행된다. $m_q$는 0.3절에서 정의한다.
3. **load.** 모든 $k$에 대해 $0\le L_k(\rho)\le 2$이다. route는 빈 상태로 시작하고 빈 상태로 끝난다. 또한 $D_q$를 수행할 때 차량에 type $\phi_q$인 빈 skip이 실려 있어야 한다.
4. **duration.** open route이므로 시작과 끝의 이동시간은 0이며, $d(\rho_k)\le T$이다.

목적은 feasibility이다. feasible solution이 여러 개이면 $\sum_k c(\rho_k)$가 작은 해를 선호한다. $K$가 고정되어 있으므로 fixed vehicle cost는 상수이다.

### 0.3 클래스

$\alpha,\beta,\phi$가 같은 request는 서로 구별하지 않는다.

- pickup class $p=(\alpha_p,\beta_p,\phi_p)$에 대해, 해당 request 수를 $m_p$로 쓴다.
- delivery class $q=(\omega_q,\phi_q)$에 대해, 해당 request 수를 $m_q$로 쓴다.

trip은 클래스 단위로 생성한다. 실제 request는 ALNS 단계에서 배정한다.

### 0.4 분해 성질과 trip의 정의

feasible route에서 물리적 skip 하나를 추적하면 $P_u\to E_u\to D_z$ ($\phi_z=\phi_u$) 형태의 부분수열이 나온다. 그러므로 모든 route는 이런 부분수열들을 끼워 섞은 것이고, 부분수열 사이를 묶는 제약은 load $\le 2$뿐이다. 이 성질에 따라 trip을 다음과 같이 정의한다.

- **single trip**: skip 1개의 궤적
- **composite trip**: skip 2개의 궤적을 끼워 섞은 것으로, 내부에서 load가 0이 되지 않는 것


## 1. Pattern generation

이 절에서는 ALNS의 기본 단위인 trip pattern의 생성 방법을 정리한다.

### 1.1 Single trip 생성

1. type이 같은 pickup class $p$와 delivery class $q$의 쌍마다 trip을 만든다.

$$
\tau_{pq}=(P_p,E_p,D_q),\qquad \phi_q=\phi_p.
$$

2. duration과 cost를 계산한다.

$$
d(\tau_{pq})=s^p+s^e+s^d+t_{\alpha_p\beta_p}+t_{\beta_p\omega_q},\qquad
c(\tau_{pq})=c_{\alpha_p\beta_p}+c_{\beta_p\omega_q}.
$$

3. duration 조건을 만족하는 trip만 남긴다. single trip은 load가 1 이하이므로 용량 검사가 필요 없다.

$$
\Omega^{\text{single}}=\{\tau_{pq}:\ \phi_q=\phi_p,\ d(\tau_{pq})\le T\}.
$$

4. 각 trip에 다음을 저장한다: 시작 위치 $h(\tau_{pq})=\alpha_p$, 끝 위치 $g(\tau_{pq})=\omega_q$, $d$, $c$, 처리하는 pickup $p$와 delivery $q$.
5. 각 $p$에 대해 trip 목록 $\Lambda_p$를 $d$ 오름차순으로 정렬한다. $d$가 같으면 $c$ 오름차순으로 정렬한다.

$q$를 같은 type 전체로 열어 두었으므로 switch-out chain도 single trip을 연결해 표현할 수 있다.

$$
(P_1E_1D_2)\oplus(P_2E_2D_3)\oplus(P_3E_3D_1).
$$

### 1.2 Composite trip 생성

**정의.** pickup class 쌍 $(p,p')$에 대해 작업 6개 $P_p,E_p,P_{p'},E_{p'},D_{q_1},D_{q_2}$를 늘어놓은 수열 $\pi=(o_1,\dots,o_6)$을 생각한다. 아래에서는 $r=p$, $s=p'$로 쓰고 $r$을 먼저 싣는다. $k$번째 작업 직후의 load를 $L_k$라 할 때 다음을 만족해야 한다.

$$
L_k=\#\{P\in o_{1..k}\}-\#\{D\in o_{1..k}\},\qquad
0<L_k\le 2\ (k=1,\dots,5),\qquad L_6=0.
$$

내부에서 $L_k=0$이 되는 수열은 single trip 두 개를 연결한 것과 같으므로 제외한다.

**Skeleton.** 위 조건을 만족하는 작업 순서는 아래 6개뿐이다. 근거는 다음과 같다. $o_1=P_r$이어야 한다. $P_r$ 바로 다음에는 $D$가 올 수 없다. $P_rE_r$ 다음에 $D$가 오면 $L=0$이 되므로 다음 작업은 $P_s$뿐이다.

| | 작업 순서 | $L_1,\dots,L_6$ | 조건 |
|---|---|---|---|
| S1 | $P_r\to E_r\to P_s\to E_s\to D_{q_1}\to D_{q_2}$ | $1,1,2,2,1,0$ | - |
| S2 | $P_r\to E_r\to P_s\to D_{q_1}\to E_s\to D_{q_2}$ | $1,1,2,1,1,0$ | $\phi_{q_1}=\phi_r$ |
| S3 | $P_r\to P_s\to E_r\to E_s\to D_{q_1}\to D_{q_2}$ | $1,2,2,2,1,0$ | - |
| S4 | $P_r\to P_s\to E_r\to D_{q_1}\to E_s\to D_{q_2}$ | $1,2,2,1,1,0$ | $\phi_{q_1}=\phi_r$ |
| S5 | $P_r\to P_s\to E_s\to E_r\to D_{q_1}\to D_{q_2}$ | $1,2,2,2,1,0$ | - |
| S6 | $P_r\to P_s\to E_s\to D_{q_1}\to E_r\to D_{q_2}$ | $1,2,2,1,1,0$ | $\phi_{q_1}=\phi_s$ |

모든 skeleton에서 duration은 $d(\pi)=2(s^p+s^e+s^d)+\mathrm{TT}(\pi)$이며, 이동시간 $\mathrm{TT}(\pi)$는 다음과 같다. cost는 $t$를 $c$로 바꾸어 계산한다.

$$
\begin{aligned}
\mathrm{TT}(S1)&=t_{\alpha_r\beta_r}+t_{\beta_r\alpha_s}+t_{\alpha_s\beta_s}+t_{\beta_s\omega_{q_1}}+t_{\omega_{q_1}\omega_{q_2}}\\
\mathrm{TT}(S2)&=t_{\alpha_r\beta_r}+t_{\beta_r\alpha_s}+t_{\alpha_s\omega_{q_1}}+t_{\omega_{q_1}\beta_s}+t_{\beta_s\omega_{q_2}}\\
\mathrm{TT}(S3)&=t_{\alpha_r\alpha_s}+t_{\alpha_s\beta_r}+t_{\beta_r\beta_s}+t_{\beta_s\omega_{q_1}}+t_{\omega_{q_1}\omega_{q_2}}\\
\mathrm{TT}(S4)&=t_{\alpha_r\alpha_s}+t_{\alpha_s\beta_r}+t_{\beta_r\omega_{q_1}}+t_{\omega_{q_1}\beta_s}+t_{\beta_s\omega_{q_2}}\\
\mathrm{TT}(S5)&=t_{\alpha_r\alpha_s}+t_{\alpha_s\beta_s}+t_{\beta_s\beta_r}+t_{\beta_r\omega_{q_1}}+t_{\omega_{q_1}\omega_{q_2}}\\
\mathrm{TT}(S6)&=t_{\alpha_r\alpha_s}+t_{\alpha_s\beta_s}+t_{\beta_s\omega_{q_1}}+t_{\omega_{q_1}\beta_r}+t_{\beta_r\omega_{q_2}}
\end{aligned}
$$

S4와 S6은 $\beta_r=\beta_s$일 때 처리시설을 두 번 방문한다. 이동시간이 non-metric이므로 이 경우도 남긴다.

**생성 절차.**

1. **pickup 쌍.** 순서쌍 $(p,p')$를 고른다. $p=p'$인 경우에는 $m_p\ge 2$여야 한다.
2. **배달 쌍 후보.** $\Lambda_p(\kappa)$를 $\Lambda_p$의 앞쪽 $\kappa$개 trip이 가리키는 delivery class 집합이라 하고, 다음을 만든다. $\kappa=1$이면 논문의 best single trip 결합과 같다.

$$
M_{pp'}=\bigl\{\{q_1,q_2\}:\ q_1\in\Lambda_p(\kappa),\ q_2\in\Lambda_{p'}(\kappa),\ q_1\ne q_2\ \text{또는}\ m_{q_1}\ge 2\bigr\}.
$$

3. **$D$ 순서.** S1, S3, S5에서는 $(q_1,q_2)$와 $(q_2,q_1)$ 두 순서를 모두 만든다. S2, S4, S6에서는 가운데 $D$가 표의 type 조건을 만족하는 순서만 만든다.
4. **duration 필터.** $d(\pi)\le T$인 수열만 남긴다.
5. **중복 제거.** 위치 순서와 작업 종류가 완전히 같은 수열은 하나만 남긴다. 예를 들어 $\beta_r=\beta_s$이면 S3과 S5, S4와 S6이 같아지고, $q_1$과 $q_2$가 같은 class이면 두 $D$ 순서가 같아진다.
6. **dominance 제거.** 같은 single trip 두 개를 연결한 수열 $\sigma$를 만든다. 연결 순서를 바꾼 경우와, type이 허용하면 $q_1,q_2$를 맞바꾼 경우도 포함한다.

$$
\sigma=\tau_{pq_1}\oplus\tau_{p'q_2},\qquad
d(\sigma)=d(\tau_{pq_1})+t_{\omega_{q_1}\alpha_{p'}}+d(\tau_{p'q_2}),\qquad
h(\sigma)=\alpha_p,\ g(\sigma)=\omega_{q_2}.
$$

   아래 조건을 모두 만족하는 $\sigma$가 하나라도 있으면 $\pi$를 버린다.

$
h(\sigma)=h(\pi),\quad g(\sigma)=g(\pi),\quad d(\sigma)\le d(\pi).
$

   이 제거로 feasible solution을 잃지 않는다. route 안의 $\pi$를 $\sigma$로 바꿔도 양 끝 위치가 같으므로 route의 나머지 부분은 그대로이고, 양 끝에서 load가 0이므로 용량 조건도 유지된다. duration은 늘지 않고 route 수도 바뀌지 않으므로 fixed-$K$ 문제에서도 유효하다. 다만 cost는 비교하지 않으므로, $d$는 같거나 더 길지만 $c$가 더 작은 composite도 함께 제거된다. 따라서 이 제거는 feasibility에는 영향을 주지 않고, 해의 cost 품질에만 영향을 줄 수 있다.

7. **저장.** $\pi$를 $\Omega^{\text{comp}}$에 넣고 $h,g,d,c$와 saving을 함께 저장한다.

$
\Delta(\pi)=\min_{\sigma}d(\sigma)-d(\pi).
$

   여기서 $\min$은 양 끝 위치와 상관없이 Step 6에서 만든 연결 수열 $\sigma$ 전체에 대해 취한다. Step 6은 양 끝 위치가 같은 $\sigma$하고만 비교하므로, Step 6을 통과한 composite도 $\Delta(\pi)\le 0$일 수 있다. 예를 들어 순서를 바꾼 $\tau_{p'q_2}\oplus\tau_{pq_1}$은 시작 위치가 $\alpha_{p'}$이므로 Step 6의 비교 대상에서 빠지지만, $\Delta$를 계산할 때는 포함된다.


### 1.3 Trip 점수와 similarity

- **trip selection.** 같은 pickup class $p$의 single trip끼리, 그리고 같은 쌍 $(p,p')$의 composite trip끼리 비교해 하나를 고른다. 순위는 $d$ 오름차순이며, $d$가 같으면 $c$ 오름차순이다. fixed-$K$에서 duration feasibility를 맞추는 것이 목적이기 때문이다. greedy selection은 1순위를 고르고, roulette-wheel selection은 $1/d$에 비례하는 확률로 고른다.
- **similarity.** 점수에는 넣지 않고 Shaw removal과 Shaw insertion에서만 쓴다. $\alpha$와 $\beta$를 같은 방식으로 다룬다.

$$
\mathrm{SIM}_{pp'}=s_1\frac{1}{1+t_{\alpha_p\alpha_{p'}}}+s_2\frac{1}{1+t_{\beta_p\beta_{p'}}}+s_3\,\mathbb 1[\phi_p=\phi_{p'}].
$$

  각 항의 의미는 다음과 같다. 첫째 항은 $P\,P$를 연속으로 할 때의 이득, 둘째 항은 $E\,E$를 연속으로 할 때의 이득, 셋째 항은 두 $D$를 맞바꿀 수 있는지이다. 첫째와 둘째 항은 $p\ne p'$인 전체 쌍의 최솟값과 최댓값으로 min-max 정규화해 $[0,1]$로 맞춘다. 셋째 항은 원래 0 또는 1이다.
- saving insertion은 composite trip을 $\Delta(\pi)$ 내림차순으로, single trip을 $d$ 오름차순으로 삽입한다.

### 1.5 기존 해와의 대조와 ALNS와의 연결

`SPDP_output_TF2_capacity_cut_travel_time_cut_ver2`의 sol 파일 62개에서 각 route를 $L=0$이 되는 지점마다 잘라 block으로 나누었다. 결과는 다음과 같다.

- 전체 block 790개 중 pickup이 1개인 block은 4개, 2개인 block은 526개, 3개 이상인 block은 260개이다.
- **pickup 2개 block의 형태는 $PPEEDD$ 525개, $PPEDED$ 1개이다. S1과 S2는 관찰되지 않았다. $\rightarrow$ 추후 옵션으로 $PPEEDD$ pattern만 사용하는 것을 고려해볼만 하다.**
- request 기준으로는 전체 2,159개 중 1,103개(51%)가 pickup 3개 이상인 block에 속한다. 자주 나온 형태는 $PPEDPEEDD$(68), $PPEEDPDPEEDD$(50), $PPEEDPEDD$(44)이다.

pickup 3개 이상인 block은 trip을 $L=0$ 지점에서 연결하는 것만으로는 만들 수 없다. 대신 single trip의 작업을 쪼개어 끼워 넣으면 만들어진다. 예를 들어 첫 번째 형태는 S4에 $\tau_{uz}$를 끼워 넣은 것이다.

$$
P_r\,P_s\,E_r\,D_{q_1}\,\underline{P_u}\,E_s\,\underline{E_u}\,D_{q_2}\,\underline{D_z},\qquad L=1,2,2,1,2,2,2,1,0.
$$

따라서 ALNS repair에는 **interleaved insertion**을 포함한다. 이는 $P_u,E_u,D_z$를 위치 $i\le j\le k$에 각각 넣되 모든 지점에서 $L\le 2$를 지키는 삽입이다. 0.4절의 분해 성질에 따라 이 삽입까지 포함하면 표현하지 못하는 route 구조가 없다. 논문에서 staging이 없을 때 single trip을 둘로 나누어 삽입하는 연산과 같은 역할을 한다.

## 2. Construction algorithm

$K=\hat k_D$대의 route로 모든 작업을 덮는 초기 완전해 $S_0$를 만든다. 0.2절의 조건 1–3(coverage, load)은 그대로 지키고, 조건 4(duration)만 penalty로 바꾸어 완화한다.

### 2.1 완화된 문제

route별 $T$ 초과량을 모두 더한 값을 $V(S)$로 둔다.

$$
V(S)=\sum_{k=1}^{K}\max\{0,\ d(\rho_k)-T\}
$$

완화된 문제는 다음과 같다.

$$
\min_{S}\ \Bigl(V(S),\ \sum_{k}c(\rho_k)\Bigr)\ \text{(사전식)}
\qquad\text{s.t. 0.2절 조건 1–3, route 수}\le K.
$$

- $V(S_0)=0$이면 $S_0$가 바로 feasible incumbent이므로 Phase I을 건너뛴다. 이때 `phase2-enable`=1이면 PALNS에서 찾은 경우와 똑같이 Phase II로 넘어가고, 0이면 바로 반환한다. $V(S_0)>0$이면 $S_0$를 ALNS의 시작해로 쓴다.

### 2.2 Route 표현과 삽입 위치

- route $\rho=(o_1,\dots,o_m)$는 작업 수열이며, $d(\rho)$와 $c(\rho)$는 0.1절의 식으로 계산한다. ALNS의 destroy 단계에서 쓰기 위해 각 작업에는 그 작업이 속한 trip의 label을 함께 저장한다.
- $L_k(\rho)$는 작업 $o_k$ 직후의 load이고, $L_0=L_m=0$이다.
- trip $B=(b_1,\dots,b_n)$의 $i$번째 작업 직후 내부 load를 $\lambda_i(B)$라 하고, 그 최댓값을 $\bar\lambda(B)=\max_i\lambda_i(B)$로 둔다. single trip은 $\bar\lambda=1$, composite trip은 $\bar\lambda=2$이다.
- **연속 삽입.** construction 단계에서는 trip은 쪼개지 않는다. 연속한 작업 묶음 그대로 $o_k$와 $o_{k+1}$ 사이, 즉 간격 $k\in\{0,\dots,m\}$에 넣는다. 삽입할 수 있는 간격의 집합은 다음과 같다.

$$
\mathcal G(\rho,B)=\bigl\{k\in\{0,\dots,m\}:\ L_k(\rho)+\bar\lambda(B)\le 2\bigr\}
$$

  따라서 single trip은 $L_k\le 1$인 모든 간격에 넣을 수 있고, composite trip은 $L_k=0$인 간격에만 넣을 수 있다.
- **feasibility 근거.** 간격 $k$에 $B$를 넣으면 $B$ 구간의 load는 $L_k(\rho)+\lambda_i(B)\le 2$이다. $B$가 끝나면 load와 차량에 실린 skip 구성은 삽입 전의 간격 $k$ 상태로 돌아간다. $B$ 안의 $D$는 $B$가 직접 비운 skip으로 처리되므로 type 조건도 지켜진다. 그러므로 $k\in\mathcal G(\rho,B)$이면 0.2절의 조건 3이 계속 성립한다.
- **증가량.** $u=\ell(o_k)$, $v=\ell(o_{k+1})$로 둔다. duration 증가량은 다음과 같다.

$$
\Delta d(\rho,B,k)=
\begin{cases}
d(B), & m=0,\\
d(B)+t_{\ell(b_n)\,v}, & k=0,\\
d(B)+t_{u\,\ell(b_1)}, & k=m,\\
d(B)+t_{u\,\ell(b_1)}+t_{\ell(b_n)\,v}-t_{uv}, & 0<k<m.
\end{cases}
$$

  cost 증가량 $\Delta c$는 위 식에서 $d(B)$를 $c(B)$로, $t$를 $c$로 바꾸어 구한다. 초과량의 증가는 다음과 같다.

$$
\Delta V(\rho,B,k)=\max\{0,\ d(\rho)+\Delta d-T\}-\max\{0,\ d(\rho)-T\}.
$$

- **삽입 기준.** 모든 route와 모든 $k\in\mathcal G(\rho,B)$ 가운데 $(\Delta V,\ \Delta d,\ \Delta c)$가 사전식으로 가장 작은 위치를 고른다. $\Delta d$를 두 번째 기준으로 두는 이유는 $K$대가 쓸 수 있는 총 시간이 $K\cdot T$로 고정되어 있기 때문이다. $\Delta V$가 같다면 시간을 덜 쓰는 위치를 골라야 다음 삽입에 쓸 여유가 남는다. $c$는 앞의 두 기준이 같을 경우 비교하는 기준이 된다.
- trip을 쪼개어 $P_u,E_u,D_z$를 서로 다른 위치에 넣는 interleaved insertion(1.5절)은 ALNS의 repair 단계에서만 쓴다.

### 2.3 구성 절차

**Phase A. Trip cover**

1. **A0. 남은 수량 초기화.** 모든 $p$와 $q$에 대해 $\bar m_p\leftarrow m_p$, $\bar m_q\leftarrow m_q$로 둔다. 각 type $f$마다 $\sum_{p:\phi_p=f}\bar m_p=\sum_{q:\phi_q=f}\bar m_q$가 성립한다.
2. **A1. composite 선택.** 각 쌍 $(p,p')$에서 selection operator로 composite 하나 $\pi_{pp'}\in\Omega^{\text{comp}}$를 고른다. operator는 start마다 greedy($d$ 최소), random, roulette($1/d$에 비례) 중에서 무작위로 정한다. 단, 첫 start에서는 greedy를 쓴다.
3. **A2. composite 채택.** $\Delta(\pi_{pp'})>0$인 후보를 $\Delta$ 내림차순으로 살펴본다. Step 6을 통과한 composite도 $\Delta\le 0$일 수 있으므로(1.2절 Step 7) 이 검사가 필요하다. 후보가 쓰는 클래스 $p,p',q_1,q_2$의 남은 수량이 충분하면 채택하고, 각 클래스의 수량을 1씩 줄인다. $p=p'$이면 $\bar m_p$를 2 줄인다. 이 단계에서도 type별 균형은 유지된다.
4. **A3. single trip 배정.** type $f$마다 남은 pickup 인스턴스 $\bar R_f$와 delivery 인스턴스 $\bar Q_f$에 대해 assignment problem을 푼다. 두 집합의 크기는 같다.

    $$
    \min\sum_{u\in\bar R_f}\sum_{z\in\bar Q_f}\bigl(d(\tau_{p(u)q(z)})+\varepsilon\,c(\tau_{p(u)q(z)})\bigr)x_{uz},
    \qquad
    \sum_{z}x_{uz}=1,\quad \sum_{u}x_{uz}=1,\quad x_{uz}\in\{0,1\}
    $$

    $x_{uz}=1$이면 $\tau_{p(u)q(z)}$를 사용한다. $\varepsilon=10^{-6}$으로 두어 $d$가 같을 때만 $c$로 고른다. $d>T$여서 $\Omega^{\text{single}}$에 없는 조합도 이 단계에서 바로 계산해 허용한다.

5. **A4. 인스턴스 배정.** 클래스 단위로 고른 trip마다 실제 request id를 하나씩 붙인다. 이렇게 얻은 trip 집합 $\mathcal T$는 모든 $P_r,E_r$와 모든 delivery 인스턴스를 정확히 한 번씩 덮는다.

**Phase B. 삽입**

1. **B0.** 빈 route $\rho_1,\dots,\rho_K$에서 시작한다.
2. **B1. 삽입 순서.** start마다 다음 셋 중 하나를 무작위로 정한다. 첫 start에서는 $d$ 내림차순을 쓴다.
   - $d(\tau)$ 내림차순(LPT): 긴 trip을 먼저 넣어 route별 duration을 고르게 맞춘다.
   - 무작위 순서
   - 2-regret: 매 단계에서 남은 각 trip에 대해 최선 위치와 차선 위치의 $(\Delta V,\Delta d)$ 차이를 구하고, 그 차이가 사전식으로 가장 큰 trip을 먼저 넣는다.
3. **B2. 삽입.** 2.2절의 기준에 따라 최선 위치에 넣고 $L$, $d(\rho)$, $c(\rho)$를 갱신한다.
4. **B3.** $\mathcal T$가 빌 때까지 B2를 반복한다.

**Multi-start**

Phase A–B를 최대 $L_{construct}$ 시간 동안 반복한다. 어느 start에서든 $V(S)=0$이 되면 그 해를 incumbent로 반환하고 즉시 종료하거나 남은 시간 동안 ALNS에서 $c$를 감소시키는 것을 수행한다. 끝까지 $V(S)=0$인 해가 없으면 $(V,\sum c)$가 사전식으로 가장 작은 해를 $S_0$로 삼아 ALNS에 넘긴다.

### 2.4 완전해 보장

- **Phase A는 항상 끝난다.** A2에서 채택하는 composite는 type별로 pickup과 delivery를 같은 수만큼 소비하므로 남은 수량의 균형이 깨지지 않는다. 따라서 A3의 assignment problem에는 항상 perfect matching이 존재한다. 또한 $T$ 필터를 적용하지 않으므로 모든 비용이 정의된다.
- **Phase B는 항상 끝난다.** 모든 route에서 $L_0=0$이므로 $0\in\mathcal G(\rho,B)$이고, 따라서 모든 trip에는 항상 삽입할 위치가 있다. 남는 제약은 $T$뿐인데 이는 penalty로 완화했으므로 삽입이 실패하지 않는다.
- 따라서 $S_0$는 0.2절의 조건 1–3을 만족하고 route 수가 $K$ 이하인 완전해이다.

## 3. PALNS

2장에서 만든 초기 완전해 $S_0$에서 시작한다. destroy, trip selection, repair, local search를 반복하면서 $V$를 0으로 줄인다. $V=0$인 해를 얻으면 그 해가 $K=\hat k_D$대의 feasible incumbent이다. $\hat k_D$는 하한이므로, 이 해는 $\hat k_D$가 최소 차량 수임을 증명하는 해이기도 하다.

### 3.1 목적함수와 단계

- **Phase I (feasibility).** 총 duration을 $D(S)=\sum_k d(\rho_k)$로 두고 다음 함수를 최소화한다.

$$
f_I(S)=V(S)+\eta\,D(S),\qquad 0<\eta\ll 1\ (\text{기본값 }\eta=0.01).
$$

  $V$만 쓰면 값이 같은 해가 많아 탐색 방향을 잡기 어렵다. 그래서 $D$를 작은 가중치로 더해 방향을 준다. $K$대가 쓸 수 있는 총 시간은 $K\cdot T$로 고정되어 있으므로, $D$를 줄이면 그만큼 여유가 생긴다.
- **$\eta$ 진동.** $\eta_{\max}$를 진동의 시작값(옵션 `phase1-eta-max`)이라 하자. $\eta_{\max}>\eta$이면 SA cycle(Step 6)마다 $\eta$를 $\eta_{\max}$에서 $\eta$까지 기하급수적으로 줄이고, 다음 cycle에서 다시 $\eta_{\max}$로 올린다. $\eta_{\max}\le\eta$이면 진동하지 않는다. cycle 초반에는 $D$를 줄여 여유를 만들고, 후반에는 $V$를 없애는 데 집중한다. $\eta$가 계속 바뀌어 $f_I$ 값끼리는 비교할 수 없으므로, 이때 최선해는 $(V,D)$ 사전식으로 판정한다.
- **Phase II (cost, 선택).** $V=0$인 해를 얻은 뒤 시간이 남아 있으면 cost를 줄인다. 실행 가능 영역 안에서만 움직이면 $d(\rho)$가 $T$에 붙은 route가 많을 때 대부분의 이동이 막힌다. 그래서 $V>0$인 해를 거쳐 갈 수 있도록 벌점 목적함수를 쓴다.

    $$
    f_{II}(S)=C(S)+\lambda\,V(S),\qquad C(S)=\sum_k c(\rho_k),\qquad \lambda_0=\max\{1,\ 2C(S)/D(S)\}.
    $$

    $\lambda_0$는 Phase II를 시작한 해로 정한다. 이후 100 iteration마다 그동안 나온 $S'$ 중 $V(S')=0$인 비율을 보고, 0.4보다 작으면 $\lambda$를 1.5배, 0.6보다 크면 $1/1.5$배로 바꾼다 ($\lambda\in[10^{-3},10^{6}]$). 최선해 $S^\star$는 $V=0$인 해 가운데 $C$가 가장 작은 해로만 갱신한다. 이렇게 얻은 해는 B&C warm start의 upper bound를 개선하는 데 쓴다.
- 이하에서 $f$는 현재 단계의 목적함수, 즉 $f_I$ 또는 $f_{II}$를 뜻한다.

### 3.2 해 표현과 제거 단위

- route는 작업 수열 $\rho=(o_1,\dots,o_m)$이다. 각 작업에는 클래스 label($P_p,E_p,D_q$)과 함께 그 작업이 속한 skip 궤적 $\kappa=(P_u,E_u,D_z)$의 label을 저장한다. 0.4절에 따라 모든 route는 이런 궤적들을 끼워 섞은 것이다.
- **제거 단위는 skip 궤적이다.** $D_z$는 $\phi_z=\phi_u$인 delivery 중 하나이며, $u$ 자신의 배달 위치일 필요는 없다. 탐색 중에는 pickup class와 delivery class의 남은 수량만 관리하면 된다. request id는 최종 해를 B&C의 node $P_r,D_r$에 대응시킬 때만 필요하며, 같은 클래스 안에서는 아무 id나 붙여도 된다.
- 궤적을 지우면 $P_u$부터 $D_z$까지 구간의 load가 1씩 줄어든다. 따라서 남은 작업은 load 조건과 type 조건을 계속 만족한다. 다만 이동시간이 non-metric이므로 $d(\rho)$는 늘어날 수도 있다.
- 제거된 궤적 집합을 $\mathcal K^-$로 두면, 다시 덮어야 할 pickup 집합 $U$와 delivery 집합 $Z$는 type별로 개수가 같다.

$$
\lvert U_f\rvert=\lvert Z_f\rvert\quad(\forall f\in F).
$$

- **block**은 $L>0$이 이어지는 최대 구간이다. block의 양 끝은 $L=0$인 간격이다.

### 3.3 Iteration 절차

**Step 1. Operator 선택.** destroy operator $\mathcal D$, selection operator $\mathcal Q$, repair operator $\mathcal R$를 각각 weight에 비례하는 확률로 하나씩 고른다. 제거할 궤적 수는 다음과 같이 뽑는다.

$$
k\sim\mathcal U\{1,\dots,k_{\max}\},\qquad k_{\max}=\max\{2,\ \lceil 0.1\,\lvert R\rvert\rceil\}.
$$

**Step 2. Destroy $S'\leftarrow\mathcal D(S,k)$.**

| operator | 제거 대상 |
|---|---|
| random | 무작위로 고른 궤적 $k$개 |
| worst | $f(S)-f(S\setminus\kappa)$가 큰 궤적 $k$개 |
| Shaw | 무작위로 고른 궤적 하나와, 그 궤적과 $\mathrm{SIM}_{p(u)p(u')}$가 큰 궤적 $k-1$개 |
| extended associated | 무작위로 고른 궤적 $k$개가 속한 block 전체 |
| overload | $d(\rho)-T$가 가장 큰 route에서 제거 이득이 가장 큰 궤적 하나와, 모든 route에서 그 궤적과 $\mathrm{SIM}$이 큰 궤적 $k-1$개. Phase II에서는 쓰지 않고, $V(S)=0$이면 worst로 대신한다 |

- 모든 궤적은 작업 수가 3으로 같다. 그래서 worst removal은 논문처럼 정류장 수로 정규화하지 않는다.
- worst, Shaw, overload는 상위 후보를 그대로 고르지 않는다. 점수 내림차순 목록에서 $\lfloor y^{p}\,n\rfloor$번째 후보($y\sim\mathcal U(0,1)$, $n$은 남은 후보 수)를 뽑아 빼는 일을 반복한다. worst는 $p=3$, Shaw와 overload는 $p=6$이다. 같은 해에서 늘 같은 궤적이 지워지는 것을 막기 위해서이다.

**Step 3. Trip selection $\mathcal C\leftarrow\mathcal Q(U,Z)$.** $\mathcal C$는 cover가 아니라 서로 겹치는 후보 집합이다. 어떤 후보를 실제로 쓸지는 Step 4에서 정한다.

- **composite 후보.** 쌍 $\{u,u'\}\subseteq U$마다 $\Omega^{\text{comp}}_{p(u)p(u')}\cup\Omega^{\text{comp}}_{p(u')p(u)}$에서 delivery class가 $Z$에 남아 있는 후보만 추린다. 그중 하나를 $\mathcal Q$로 고르고, 남은 후보가 없으면 그 쌍은 건너뛴다. 고르는 기준은 다음과 같다.
  - greedy: $d$가 최소인 후보
  - random: 무작위
  - roulette: $1/d$에 비례하는 확률
- **single 후보.** type $f$마다 $U_f$와 $Z_f$ 사이의 assignment로 고른다. 그러면 single 후보들이 하나의 perfect matching을 이루므로 서로 겹치지 않는다. pickup마다 따로 고르면 같은 delivery를 고른 single 후보끼리 서로를 지우는 일이 잦아진다. 그 결과 실제로 넣는 single trip의 상당수가 $\mathcal Q$가 고른 것이 아니라 마무리 단계에서 만든 것이 되어, selection operator의 weight가 무엇을 학습하는지 흐려진다. assignment의 비용은 $\mathcal Q$에 따라 다음과 같다.
  - greedy: $d+\varepsilon c$
  - random: $U_f$를 무작위 순서로 섞은 뒤, 순서대로 남은 delivery 중 하나를 균등 확률로 뽑는다. 결과는 무작위 perfect matching이다.
  - roulette (순차 roulette): $U_f$를 무작위 순서로 섞고 그 순서대로 $u$를 처리한다. 각 $u$에 대해 아직 남은 delivery $Z^{\text{rem}}_f$ 중에서 $z$를 아래 확률로 뽑고, 뽑힌 $z$는 $Z^{\text{rem}}_f$에서 뺀다.

    $
    \Pr(z\mid u)=\frac{1/d(\tau_{uz})}{\sum_{z'\in Z^{\text{rem}}_f}1/d(\tau_{uz'})}
    $

    처음에 $\lvert U_f\rvert=\lvert Z_f\rvert$이고 매 단계 pickup과 delivery가 하나씩 함께 빠지므로, 뽑을 delivery가 바닥나지 않고 끝에는 항상 perfect matching이 된다. 먼저 처리되는 pickup이 유리해지는 문제는 처리 순서를 무작위로 섞어 줄인다. 확률 기준은 composite 후보의 roulette과 같은 $1/d$이다.

**Step 4. Repair.**

1. **삽입 순서.** $\mathcal R$가 $\mathcal C$의 삽입 순서를 정한다. greedy와 2-regret은 trip을 하나 넣을 때마다 남은 후보를 다시 평가한다.

    | $\mathcal R$ | 순서 |
    |---|---|
    | random | 무작위 |
    | Shaw | 기준 trip과의 $\mathrm{SIM}$ 내림차순. composite는 두 pickup 사이의 $\mathrm{SIM}$으로 정렬 |
    | saving | composite를 $\Delta(\pi)$ 내림차순으로 모두 넣은 뒤, single을 $d$ 오름차순으로 넣는다 |
    | greedy | 최선 위치의 $\bigl(\Delta V/n(\tau),\ \Delta d/n(\tau)\bigr)$ 오름차순. $n(\tau)$는 trip이 처리하는 궤적 수 |
    | 2-regret | 최선 위치와 차선 위치의 $(\Delta V,\Delta d)$ 차이 내림차순 |

    Phase II의 greedy와 2-regret은 $\Delta V$ 자리에 $\Delta c+\lambda\Delta V$를 쓴다. greedy에서 $n(\tau)$로 나누는 것은 skip 하나당 비용으로 맞춰 비교하기 위해서이다. 나누지 않으면 skip 2개를 처리하는 composite가 거의 항상 뒤로 밀리고, 그 사이 single이 pickup을 먼저 덮어 composite가 충돌로 사라진다.

2. **삽입 위치.** trip $B$마다 아래 두 방식으로 후보 위치를 만든다. Phase I에서는 $(\Delta V,\Delta d,\Delta c)$가 사전식으로 가장 작은 위치에 넣는다. Phase II에서는 $(\Delta c+\lambda\Delta V,\ \Delta d)$가 사전식으로 가장 작은 위치에 넣는다.

   - **연속 삽입.** 2.2절과 같다. $k\in\mathcal G(\rho,B)$인 간격에 trip을 통째로 넣는다.
   - **분할 삽입 (single trip만).** $P_u$, $E_u$, $D_z$를 각각 간격 $i$, $j$, $k$에 넣는다 ($0\le i\le j\le k\le m$). 이 삽입이 feasible할 조건은 다음과 같다.

    $$
    L_g(\rho)\le 1\quad(\forall g\in\{i,\dots,k\}).
    $$

    작업 $x$ 하나를 간격 $g$에 넣을 때 duration 증가량은 다음과 같다. 양 끝 간격에서는 존재하지 않는 이동 항을 0으로 둔다.

    $$
    \delta_x(g)=s(x)+t_{\ell(o_g)\ell(x)}+t_{\ell(x)\ell(o_{g+1})}-t_{\ell(o_g)\ell(o_{g+1})}.
    $$

    $L\le 1$이 이어지는 구간 $W$마다, 세 간격이 모두 다른 경우($i<j<k$)의 최솟값을 앞쪽 최솟값과 뒤쪽 최솟값으로 $O(\lvert W\rvert)$에 구한다.

    $$
    \min_{i<j<k}\Delta d=\min_{j\in W}\Bigl[\min_{i<j}\delta_P(i)+\delta_E(j)+\min_{k>j}\delta_D(k)\Bigr].
    $$

    $i=j$이거나 $j=k$이면 겹치는 두 작업을 한 묶음으로 넣는 비용으로 따로 계산한다. 세 간격이 모두 같으면 연속 삽입과 같다. 같은 route 안에서는 $\Delta V$가 $\Delta d$에 대해 감소하지 않으므로, $\Delta d$를 최소로 하는 위치가 그 route에서 가장 좋은 위치이다. Phase II에서는 $\Delta c$를 최소로 하는 분할 위치도 함께 후보로 둔다. pickup이 3개 이상인 block(1.5절)은 이 삽입으로 만들어진다.

3. **충돌 제거.** trip $\tau$를 넣으면 다음 후보를 $\mathcal C$에서 지운다.
   - $\tau$가 덮은 pickup을 포함하는 후보
   - 남은 수량이 0이 된 delivery class를 쓰는 후보

4. **마무리.** $\mathcal C$가 비었는데도 아직 덮이지 않은 $U'$와 $Z'$가 남는 경우가 있다. 이 경우는 composite와의 충돌로만 생긴다. 이때 type별로 $U'_f$와 $Z'_f$ 사이의 assignment problem을 Step 3 greedy 비용 $d+\varepsilon c$로 풀어 single trip을 만들고, $d$ 내림차순으로 넣는다. type별로 $\lvert U'_f\rvert=\lvert Z'_f\rvert$가 유지되므로 이 assignment에는 항상 해가 있다.  따라서 repair는 항상 완전해를 돌려준다.

**Step 5. Local search.** 아래 이동을 $f$가 개선될 때만 적용하고, 더 이상 개선되지 않을 때까지 최대 200회 반복한다. Phase II에서도 $f_{II}$로 판단하므로 $V>0$이 되는 이동도 허용된다.

| 이동 | 내용 | feasibility 근거 |
|---|---|---|
| D-swap | type이 같은 두 $D$의 위치를 맞바꾼다 (route 안이든 route 사이든) | 각 위치의 type이 그대로이므로 load와 type 조건이 유지된다 |
| inter-route block swap | 두 route에서 block을 하나씩 골라 서로의 자리에 맞바꾼다 | block의 양 끝에서 load가 0이다 |
| inter-route block relocate | block 하나를 다른 route의 $L=0$ 간격 중 가장 좋은 곳으로 옮긴다 | 위와 같다 |
| intra-route block 재배치 | 한 route 안에서 block 하나를 옮기거나, 두 $L=0$ 간격 사이의 block 순서를 뒤집는다. block 내부의 순서는 그대로 둔다 | 위와 같다 |
| trajectory relocate | 궤적 하나를 빼고, 모든 route에서 최선 위치(분할 삽입 포함)에 다시 넣는다 | Step 4의 삽입 조건 |

- trajectory relocate는 block 내부를 다시 짜는 유일한 이동이지만 계산량이 크다. 그래서 앞의 네 이동으로 local search를 마친 $S'$가 최선해 $S^\star$에 충분히 가까울 때만, 이 이동을 포함해 local search를 한 번 더 돌린다.

$$
f(S')\le(1+r_{\text{LS}})\,f(S^\star).
$$

  $r_{\text{LS}}$는 $S^\star$보다 얼마나 나쁜 후보까지 이 이동을 적용할지 정하는 허용 비율이다(옵션 `ls-deep-ratio`). 예를 들어 $r_{\text{LS}}=0.01$이면 $S^\star$보다 1% 이내로 나쁜 후보에만 적용한다. $f\ge 0$이므로 이 비교는 항상 의미가 있다.


**Step 6. Acceptance.** simulated annealing 규칙을 쓴다. temperature는 $T$와 구별하기 위해 $\Theta$로 쓴다.

$$
S\leftarrow S'\quad\text{if}\quad f(S')<f(S)\ \ \text{or}\ \ \exp\Bigl(-\frac{f(S')-f(S)}{\Theta}\Bigr)\ge\xi,\qquad \xi\sim\mathcal U(0,1).
$$

  $S'$가 3.1절의 기준으로 $S^\star$보다 좋으면 $S^\star\leftarrow S'$로 갱신한다. Phase II에서는 연속 무개선 iteration 수 $noimp$도 관리한다. $S^\star$가 갱신되거나 병렬 portfolio의 공유 최선 비용이 갱신되면(3.5절) $noimp\leftarrow 0$으로 되돌리고, 둘 다 아니면 $noimp\leftarrow noimp+1$로 늘린다. 냉각은 iteration 수로 정한 cycle 단위로 반복한다. 기호는 다음과 같다.

  - $N_{\text{cyc}}$: cycle 하나의 iteration 수. Phase I은 옵션 `sa-cycle-iters`, Phase II는 옵션 `sa-cycle-iters-phase2`로 정한다. 후자가 0 이하이면 Phase I 값을 쓴다.
  - $\mathrm{pos}\in[0,1)$: 현재 cycle 안의 진행률. cycle 안에서 $i$번째 iteration이면 $\mathrm{pos}=(i-1)/N_{\text{cyc}}$이다.
  - $r_{\text{SA}}$: 시작 온도 비율(옵션 `sa-start-ratio`). Phase I에만 다른 값을 쓰려면 `sa-start-ratio-phase1`을 0 이상으로 준다.
  - $r_{\text{end}}$: cycle 끝 온도와 시작 온도의 비(옵션 `sa-end-ratio`, 기본값 $10^{-3}$).

  온도는 cycle 안에서 아래와 같이 $\Theta_0$에서 $r_{\text{end}}\Theta_0$까지 기하급수적으로 내려간다.

$$
\Theta=\Theta_0\,r_{\text{end}}^{\ \mathrm{pos}},\qquad \Theta_0=\frac{r_{\text{SA}}\,f(S)}{\ln 2}.
$$

  $\Theta_0$는 $f(S)$보다 $r_{\text{SA}}$ 비율만큼 나쁜 해를 확률 $1/2$로 받아들이는 온도이다. 각 단계를 시작할 때의 $S$로 정하고, $\eta$ 진동을 쓰면 cycle마다 다시 정한다. cycle이 끝나면 $S\leftarrow S^\star$로 되돌린다. 경과 시간에 맞춘 냉각은 $L_{\max}$가 길면 대부분의 시간을 높은 온도에서 보내고, iteration 속도에 따라 instance마다 냉각 정도가 달라진다. 그래서 식혀서 $S^\star$ 근처를 깊게 본 뒤 다시 데우는 과정을 반복한다.

**Step 7. Weight 갱신.** $U$번의 iteration마다 논문 식 (73)으로 destroy, selection, repair operator의 weight를 갱신한다.

$$
w_i\leftarrow(1-\varrho)\,w_i+\varrho\,\sigma^{\text{avg}}_i,\qquad
\varrho=0.1,\quad \sigma_{\text{best}}=10,\quad \sigma_{\text{cur}}=3,\quad \sigma_{\text{new}}=1.
$$

- 갱신 주기는 $U=50$이다. $\sigma^{\text{avg}}_i$는 직전 $U$번의 iteration 동안 operator $i$가 받은 보상의 평균이다. 이 기간에 한 번도 선택되지 않은 operator는 $\sigma^{\text{avg}}_i$를 정의할 수 없으므로 weight를 그대로 둔다. 갱신 뒤에는 $w_i\ge 10^{-3}$을 유지해 operator가 다시 선택될 여지를 남긴다.
- 보상은 새 최선해를 찾으면 $\sigma_{\text{best}}$, 현재해보다 좋아지면 $\sigma_{\text{cur}}$를 준다. 나빠졌지만 받아들여졌고 처음 보는 해이면 $\sigma_{\text{new}}$를 주고, 그 밖에는 0을 준다.
- **처음 보는 해의 판정.** 연속한 두 작업의 클래스 label 쌍 $(o,o')$마다 64-bit 난수 $z(o,o')$를 미리 정해 둔다. route의 시작과 끝을 나타내는 가상 작업도 포함한다. 해의 hash는 다음과 같고, 이를 hash set에 저장해 판정한다.

$$
H(S)=\sum_{k}\sum_{(o,o')\in\rho_k}z(o,o')\pmod{2^{64}}.
$$

  덧셈은 순서와 무관하므로 route 순서만 바꾼 해는 같은 hash를 받는다. XOR 대신 덧셈을 쓰는 이유는, 클래스 label에서는 같은 쌍이 두 번 나올 수 있고 XOR을 쓰면 그 두 항이 서로 지워지기 때문이다. hash 계산은 $O(\lvert R\rvert)$이다.

### 3.4 종료 조건과 출력

Phase I의 종료 조건은 시간 제한 $L_{\max}$뿐이다. Phase II에는 시간 제한에 더해 무개선 조건을 둔다.

- **Phase I.** $V(S')=0$인 해가 나오면 즉시 끝내고, 그 해를 $K=\hat k_D$의 incumbent로 저장한다. 남은 시간은 Phase II에 쓴다.
- **Phase II.** 전체 경과 시간이 $L_{\max}$에 도달하거나 아래 정체 조건이 성립하면 끝낸다. 비용 개선이 멈춘 뒤에 남은 시간까지 쓰지 않기 위해서이다. $t$는 PALNS를 시작한 뒤의 경과 시간(Phase I 포함), $t_{\text{last}}$는 공유 최선 비용이 마지막으로 개선된 시각(3.5절), $noimp$는 Step 6의 연속 무개선 iteration 수이다.

$$
\bigl(t-t_{\text{last}}\ge\gamma\,t\ \ \text{그리고}\ \ noimp\ge N^{II}_{\min}\bigr)\quad\text{또는}\quad noimp\ge N^{II}_{\max}
$$

  - $\gamma$: 정체 비율(옵션 `stag-ratio`). 지금까지 쓴 시간의 $\gamma$ 비율 동안 개선이 없으면 멈춘다. 그래서 오래 걸린 instance일수록 오래 기다린다. $\gamma\le 0$이면 이 조건을 쓰지 않는다.
  - $N^{II}_{\min}$: 최소 무개선 iteration 수(옵션 `stag-min-iters`). 실행 초반에는 $\gamma t$가 작아 짧은 공백에도 멈출 수 있으므로 이를 막는다. iteration 수로 세므로, iteration이 빠른 작은 instance는 금방 채운다.
  - $N^{II}_{\max}$: 무개선 iteration 수의 상한(옵션 `phase2-max-noimp`). 작은 개선이 띄엄띄엄 이어져 $t_{\text{last}}$가 계속 늦춰지는 instance를 끊는다.
  - 개선이 더 없다고 할 때 thread당 초당 iteration 수를 $r$이라 하면, 멈추는 시각은 다음과 같다.

$$
t_{\text{stop}}\approx\min\Bigl\{\max\Bigl\{t_{\text{last}}+\frac{N^{II}_{\min}}{r},\ \frac{t_{\text{last}}}{1-\gamma}\Bigr\},\ t_{\text{last}}+\frac{N^{II}_{\max}}{r}\Bigr\}
$$

- $L_{\max}$에 도달할 때까지 $V(S^\star)>0$이면, $K$대로는 incumbent를 찾지 못한 것이다. 이는 infeasibility의 증명이 아니다. 필요하면 $K+1$대로 다시 실행해 upper bound용 feasible solution을 얻는다.
- 검증용으로 목표 비용 $\bar C$(옵션 `target-cost`, 음수이면 사용하지 않음)를 주면, 원래 비용(이동비용 + 고정 차량비)이 $\bar C$ 이하인 해를 찾는 즉시 끝낸다.
- **출력.** 아래 순서로 B&C multigraph의 해로 바꾼다. route 복원과 duration 검사를 통과하면 MIP start로 넘긴다.
  1. 쓰인 route가 $K$개보다 적으면 block 경계에서 잘라 $K$개로 맞춘다. (어차피 K는 검증된 LB라 발생하지는 않는다.)
  2. multigraph의 symmetry pruning에 맞춘다. 같은 위치에서 연속한 $P\to D$, $E\to P$, $D\to E$는 순서를 바꾼다(41a–c). 이동시간이 0이므로 $d$와 $c$는 변하지 않는다. 같은 위치에서 연속한 pickup끼리, delivery끼리는 request 번호가 증가하도록 id를 붙인다(40a/40c). 그 밖에는 같은 클래스 안에서 아무 id나 붙인다.
  3. 연속한 두 서비스 작업 사이(처리시설 방문 포함)를, 시작 상태와 끝 상태가 같은 평행 edge로 바꾼다. 처리시설 순서와 시간이 같은 edge를 먼저 쓰고, 없으면 시간과 비용이 모두 같거나 작은 edge를 쓴다. multigraph는 Pareto edge를 모두 남기므로 둘 다 없으면 pruning과 route 표현이 어긋난 것이고, adapter error로 처리한다.

### 3.5 병렬 portfolio

2장의 construction부터 3.4절의 종료까지를 여러 thread에서 동시에 돌린다. 기호는 다음과 같다.

- $n_{\text{th}}$: thread 수(옵션 `threads`). thread 번호는 $i=0,\dots,n_{\text{th}}-1$이다.
- $\text{seed}$: 난수 seed(옵션 `seed`). thread $i$는 $\text{seed}_i=\text{seed}+7919i$를 쓰고, 차량 수 $K$마다 난수 생성기를 $\text{seed}_i\cdot 1000003+K$로 초기화한다. 그래서 thread마다 construction부터 서로 다른 해에서 출발한다.

thread 사이의 동작은 아래와 같다.


- $V=0$인 해를 찾은 thread는 그 해를 공유 저장소에 올린다. 저장소는 그중 $C$가 가장 작은 해를 보관한다. 공유 최선 비용이 개선된 시각 $t_{\text{last}}$와 개선 기록(시각, 원래 비용)도 함께 보관하며, 개선 기록은 `[palns-shared-trace]` 로그로 출력한다.
- 짝수 thread는 Phase I에서 64 iteration마다 저장소를 확인하고, 해가 있으면 받아서 Phase II로 넘어간다. Phase II에서는 cycle이 끝날 때 저장소의 해가 자기 $S^\star$보다 좋으면 받는다.
- 홀수 thread는 저장소를 보지 않고 독립적으로 탐색해 출발점의 다양성을 유지한다.
- 한 thread가 3.4절의 조건으로 끝나면 나머지 thread도 모두 멈춘다. 출력은 thread별 $S^\star$ 중 비용이 가장 작은 해이다. $noimp$는 thread마다 세지만, 어느 thread든 공유 최선 비용을 개선하면 모든 thread의 $noimp$가 0으로 돌아간다. 따라서 3.4절의 $noimp\ge N$($N=N^{II}_{\min}$ 또는 $N^{II}_{\max}$)은 portfolio 전체가 그 thread의 $N$ iteration 동안 한 번도 개선되지 않았다는 뜻이다. thread별로만 세면, 같은 공유 해에서 Phase II를 시작한 짝수 thread 하나가 금방 정체해 다른 thread가 개선 중인데도 전체가 멈춘다. thread 사이의 타이밍에 따라 결과가 달라지므로, seed가 같아도 결과가 재현되지 않는다.

## 4. 구현 옵션

PALNS는 기존 initial incumbent 구조 안에 새 backend로 추가한다. 새 옵션의 이름은 모두 `--initial-incumbent-palns-` 접두사를 붙인다. 아래 표에서는 접두사를 생략한다.

### 4.1 기존 옵션과의 연결

| 옵션 | 값 | 내용 |
|---|---|---|
| `--initial-incumbent-backend` | `two-index-milp`, `cp-sat`, `palns` | `palns`를 새로 추가한다 |
| `--initial-incumbent-time-limit` | 기존 값 | K 시도 1회의 시간 제한 $L_{\max}$이다. construction, Phase I, Phase II를 모두 포함하며, 이들 사이에 시간을 나누지 않는다 |
| `--initial-incumbent-timeout-action` | `stop`, `advance` | $L_{\max}$ 안에 $V=0$인 해를 찾지 못하면 멈추거나(`stop`) $K+1$로 넘어간다(`advance`) |
| `--initial-incumbent-max-k-increments` | 기존 값 | $K$를 늘려 다시 시도하는 최대 횟수이다 |

- **pattern generation 시간.** pattern pool은 $K$와 무관하므로 instance마다 한 번만 만들고, 모든 K 시도에서 재사용한다. $L_{\max}$는 pattern 생성 전에 정해지므로 생성 시간은 $L_{\max}$에 들어가지 않는다. 반면 instance 전체 예산(`INSTANCE_TIME_LIMIT`)은 실제 경과 시간으로 재므로, 생성 시간도 이 예산에서 빠진다.
- **construction의 시간 처리.** multi-start 도중에 남은 시간이 0이 되면, 그때까지 얻은 최선해를 $S_0$로 삼고 끝낸다. 다만 이 해는 warm start로 사용할 수 없다.
- **feasible solution을 찾았을 때.** $V=0$인 해를 construction에서 찾든 PALNS Phase I에서 찾든 같은 규칙을 따른다. `phase2-enable`=1이면 Phase II로 넘어가고, 0이면 바로 반환한다.

| | `ls-first-improvement` | 1 | 1이면 first improvement, 0이면 best improvement |
| Phase II | `phase2-enable` | 1 | $V=0$인 해를 찾은 뒤 cost 개선 단계를 실행할지 |
| | `phase2-max-noimp` | 2000 | $N^{II}_{\max}$ (무개선 iteration 상한) |
| | `stag-ratio` | -1 | $\gamma$. 0 이하이면 비율 조건을 쓰지 않는다 |
| | `stag-min-iters` | 5000 | $N^{II}_{\min}$ |

`composite-skeletons`=`S3,S5`로 두면 S4와 S6은 생성하지 않는다. 기존 해에서 S4와 S6 형태($PPEDED$)는 1번만 관찰되었기 때문이다. $\beta_r=\beta_s$이면 S5는 S3과 같으므로, 이 경우에는 S3 하나만 남는다.

### 4.3 실행 설정

`run_release_many.sh`의 `# INPUT PARAMETERS`에 있는 incumbent 관련 변수와 현재 값이다. PALNS 변수는 `INITIAL_INCUMBENT_BACKEND=palns`일 때만 쓰인다. 코드에 고정된 상수($\varrho$, $\sigma$, $U$, $\lambda$ 조정 규칙 등)는 3장 본문에 적었다.

**주요 설정**

| 변수 | 스크립트 값 | 설명 |
|---|---|---|
| `INITIAL_INCUMBENT_BACKEND` | `palns` | incumbent를 구하는 backend(`two-index-milp`, `cp-sat`, `palns`). `palns`일 때만 아래 PALNS 변수가 쓰인다 |
| `INITIAL_INCUMBENT_TIME_LIMIT` | `600` | $K$ 시도 1회의 시간 제한 $L_{\max}$(초). construction, Phase I, Phase II를 포함하고 pattern 생성은 포함하지 않는다. 기준 실행에서 가장 늦게 baseline 비용에 도달한 C17이 약 490초였다 |

Phase II 종료 값($\gamma$, $N^{II}_{\min}$, $N^{II}_{\max}$)의 후보는 아래와 같다. 가장 오래 기다리는 설정($\gamma=0.8$, $N^{II}_{\min}=50000$)으로 65개를 한 번 돌린 기록에서, 덜 기다리는 조합의 결과를 계산했다(`palns_stag_analysis/`). 세 후보 모두 62개 instance가 baseline 비용 이하이고 C12, C16, C19의 incumbent를 찾는다. 시간은 $L_{\max}=600$초 기준이며, 기본값은 균형이다.

| 후보 | $\gamma$ | $N^{II}_{\min}$ | $N^{II}_{\max}$ | 62개 시간 합 | 시간 기준 통과 |
|---|---|---|---|---|---|
| 공격적 | 0.60 | 30000 | 75000 | 1706초 | 18 |
| 균형 | 0.60 | 30000 | 200000 | 2188초 | 17 |
| 보수적 | 0.65 | 50000 | 200000 | 2926초 | 12 |

시간 기준 통과는 baseline 시간의 1.2배 이하 또는 1초 이하인 instance 수이다. 이 기록에서 C14는 $\gamma<0.56$, B8과 C9는 $N^{II}_{\min}=20000$, C14는 $N^{II}_{\max}=50000$에서 baseline보다 나빠진다. 공격적과 균형은 이 경계에 가깝고, C17은 실행마다 결과가 크게 달라 공격적 후보의 짧은 상한에서 실패할 위험이 크다.
