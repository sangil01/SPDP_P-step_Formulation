# Branch-and-Price algorithm

## Master problem

Let $R^p$ be the full feasible compact $p$-step column set. For each column $r\in R^p$, let $x_r$ be its master variable. The column coefficients are:

- $a_r^i$: visit coefficient of service node $i$
- $s_r^{i,\sigma}$: state-balance coefficient at $(i,\sigma)$
- $q_r^{i,\sigma}$: time-link coefficient at $(i,\sigma)$
- $b_e^r$: incidence of original graph edge $e$ in column $r$

The projected original edge variable is $\theta_e$. Then the phase-2 LP at a branch node is

$$
\min \sum_{r\in R^p} c_r x_r
$$

subject to

$$
\sum_{r\in R^p} a_r^i x_r = 2 \quad \forall i\in V\setminus\{0,2n+1\},
$$

$$
\sum_{r\in R^p} s_r^{i,\sigma} x_r = 0
\quad
\forall i\in V\setminus\{0,2n+1\},\ \forall \sigma\in\Sigma_i^+,
$$

$$
\sum_{r\in R^p} q_r^{i,\sigma} x_r \ge 0
\quad
\forall i\in V\setminus\{0,2n+1\},\ \forall \sigma\in\Sigma_i^+,
$$

$$
\sum_{r\in R^p} b_e^r x_r = \theta_e \quad \forall e\in E,
$$

$$
x_r \ge 0 \quad \forall r\in R^p,
$$

$$
0 \le \theta_e \le 1 \quad \forall e\in E.
$$

At phase 1, the same master is augmented with artificial variables exactly as in the root-node note, and phase 1 terminates when all artificials are zero.

## Branch-and-price flow

### 1. Root node LP optimal solution

First solve the root-node LP relaxation by the current two-phase column-generation framework.

At the root, there is no branch fixing yet, so

$$
E_0^0 = \varnothing,
\qquad
E_0^1 = \varnothing.
$$

After the root LP is solved to optimality, inspect the projected edge variables $\theta_e$.

- If $\theta_e \in \{0,1\}$ for all $e\in E$, then the root solution is already integer and branch-and-price terminates.
- Otherwise, choose one fractional edge and branch on its $\theta_e$ value.

### 2. Branching rule

At a fractional node, choose an edge $e^\star$ with

$$
0 < \theta_{e^\star}^\star < 1.
$$

A simple first rule is to select the edge whose value is closest to $0.5$:

$$
e^\star \in \arg\min_{e:\ 0<\theta_e^\star<1}\left|\theta_e^\star-\frac12\right|.
$$

Then create two children:

1. zero-child:

$$
E_{n0}^0 = E_n^0 \cup \{e^\star\},
\qquad
E_{n0}^1 = E_n^1
$$

2. one-child:

$$
E_{n1}^0 = E_n^0,
\qquad
E_{n1}^1 = E_n^1 \cup \{e^\star\}
$$

So each branch node $n$ is represented by two edge-fixing sets $E_n^0 \subseteq E$ and $E_n^1 \subseteq E$ with $E_n^0 \cap E_n^1 = \varnothing$, meaning

$$
\theta_e = 0 \quad \forall e\in E_n^0,
\qquad
\theta_e = 1 \quad \forall e\in E_n^1.
$$

In the current implementation, this branch state is translated into the node master as follows.

1. zero-child:

$$
\theta_{e^\star} = 0.
$$

2. one-child:

$$
\theta_{e^\star} = 1.
$$

3. In addition, for one-child, the implementation builds node-level required outgoing / incoming maps from the whole forced-edge set $E_n^1$. Therefore, if some forced edge $e = (u,v)\in E_n^1$, any edge

$$
\hat e = (u,w),\ \hat e \neq e^\star,
\qquad\text{or}\qquad
\hat e = (z,v),\ \hat e \neq e^\star
$$

is inconsistent with the node's required-edge state, and is also fixed to

$$
\theta_{\hat e}=0
$$

in the node master as implied zero-fixings.

To avoid duplicate nodes efficiently, the implementation should use packed edge masks for the branch state. Concretely, each node stores:

1. a forbidden-edge bitset for $E_n^0$,
2. a forced-edge bitset for $E_n^1$,
3. a hashable key built directly from those two packed masks.

Then duplicate checking is performed by comparing this packed key before the child is inserted into the open-node list. This is heavier than parent-pointer storage in pure node-memory terms, but for the current branch-and-price design it is preferable because branch-state membership queries and duplicate checks will be frequent, especially in pricing with forbidden edges.

### 3. Node selection rule

After branching, the next node to process is determined by the node-selection rule.

1. depth-first search:
   - in the current implementation, both children are still solved immediately after branching,
   - then the open-node list is managed in LIFO order,
   - so the next node selected is the most recently inserted open node.

2. best-bound search:
   - first evaluate the newly created children to obtain their LP lower bounds,
   - then compare them with all the other already evaluated open nodes,
   - choose the open node with the smallest lower bound.

So in the current implementation, both `DFS` and `best-bound` keep evaluated LP bounds for every open node. The difference is only the open-node selection rule:

1. `DFS`: choose the most recently inserted open node,
2. `best-bound`: choose the open node with the smallest LP lower bound.

### 4. Initial column set at a selected node

Suppose node $n$ is selected from the open list.

Construct its initial restricted master problem from the parent node information. A simple first policy is:

1. inherit the parent columns,
2. remove any inherited column that uses an edge in $E_n^0$,
3. remove any inherited column containing an edge that violates the required outgoing / incoming rule induced by the current forced-edge set $E_n^1$,
4. keep the remaining columns as the initial RMP at node $n$.

So in the current implementation, both zero-child forbidden-edge filtering and one-child required-rule filtering are applied immediately at column inheritance.

If memory reduction becomes important later, additional column clean-up rules can be added, but this is the simplest starting point.
### 5. Pricing with branched edges

At node $n$, the reduced cost of a column $r$ is still

$$
\bar c_r
=
c_r
- \sum_i a_r^i \alpha_i
- \sum_{i,\sigma} s_r^{i,\sigma} \beta_{i,\sigma}
- \sum_{i,\sigma} q_r^{i,\sigma} \gamma_{i,\sigma}
- \sum_e b_e^r \delta_e.
$$

The formula itself does not change; only the node LP and its dual solution change.

The branch fixing is reflected in pricing as follows.

1. If $e\in E_n^0$, then any column with $b_e^r=1$ is infeasible and must be excluded.
2. If $E_n^1$ forces an outgoing edge at some node $u$ or an incoming edge at some node $v$, then every edge conflicting with those required outgoing / incoming choices is also infeasible at that node and must be excluded.

Implementation-wise:

1. in labeling pricing, a transition is blocked if it uses
   - a forbidden edge, or
   - an edge violating the required outgoing / incoming rule induced by a forced edge;
2. in full-enumeration pricing, an entry is marked forbidden if
   - it contains a forbidden edge, or
   - it contains an edge violating the required outgoing / incoming rule.

Once a full-enumeration entry is marked forbidden, all of its tau variants are skipped together at that node.

### 6. Phase 1 at a selected node

At node $n$, solve phase 1 first.

1. Fix $\theta_e = 0$ for $e\in E_n^0$ and $\theta_e = 1$ for $e\in E_n^1$ to the node master.
2. Inherit the parent active column set, and immediately remove any inherited column that uses a forbidden edge or violates the required outgoing / incoming rule.
3. Solve the phase-1 restricted master from that inherited column set.
4. Run pricing until all artificial variables become zero or infeasibility is proven.

If phase 1 is infeasible, prune the node immediately.

### 7. Phase 2 at a selected node

If phase 1 becomes feasible, switch to the true objective and solve phase 2.

1. Repeatedly solve the node RMP.
2. Run pricing under the current branch fixing.
3. Stop when no column with

$$
\bar c_r < -\epsilon
$$

exists.

Inside phase 2, after new columns are added, the node RMP is reoptimized on the current restricted master. Here primal simplex is the natural method, because the restricted master is expanded mainly by column additions.

Then the current solution is the LP optimum of node $n$.

### 8. Bounding, integrality test, and pruning

Let the LP optimum at node $n$ be $LB_n$. Let the current best integer incumbent value over the whole tree be $UB$.

For the current first implementation, initialize $UB$ from the known baseline value of the instance:

| instance       | baseline UB |
| -------------- | ----------: |
| RecDep_day_A1  |         648 |
| RecDep_day_A2  |         625 |
| RecDep_day_A3  |         619 |
| RecDep_day_A4  |         695 |
| RecDep_day_A5  |         707 |
| RecDep_day_A6  |        1202 |
| RecDep_day_A7  |        1211 |
| RecDep_day_A8  |        1314 |
| RecDep_day_A9  |        1244 |
| RecDep_day_A10 |        1297 |
| RecDep_day_A11 |        1289 |
| RecDep_day_B1  |        1299 |
| RecDep_day_B2  |        1121 |
| RecDep_day_C1  |        1297 |
| RecDep_day_C2  |        1438 |
| RecDep_day_C3  |        2269 |
| RecDep_day_C4  |        1520 |

Later, this should be replaced by a heuristic incumbent generation procedure at the root.

Then:

1. If node $n$ is phase-1 infeasible, prune it.
2. If $LB_n \ge UB$, prune it by bound.
3. If $\theta_e \in \{0,1\}$ for all $e\in E$, treat node $n$ as integer, update the incumbent if improved, and prune the node.
4. Otherwise, node $n$ remains fractional and must be branched further.

Here integrality is checked on the projected edge variables $\theta$, not on the column variables $x_r$.

Also, since all edge costs $c_{ij}$ are integer in the current instances, the node costs and route costs are integer as well. Therefore, if

$$
UB - LB_n < 1,
$$

then no better integer solution can exist below node $n$, so the node can be terminated by integrality-gap rounding as well.

At the global tree level, if

$$
UB - \min_{m\in \mathcal{O}} LB_m < 1,
$$

where $\mathcal{O}$ is the current open-node set, then the whole branch-and-price algorithm can terminate as well.

For numerical handling:

1. use the usual reduced-cost tolerance $-\epsilon$ for pricing,
2. use an integrality tolerance for $\theta_e$, for example treating $\theta_e \le 10^{-6}$ as $0$ and $\theta_e \ge 1-10^{-6}$ as $1$,
3. apply the gap test with a small floating tolerance in implementation.

### * pool data structure modification

For full-enumeration pricing, the pool itself should be separated into:

1. a shared immutable static pool object,
2. a node-local mutable state.

The static pool stores the entry/variant metadata, edge-incidence information, and matrix data. The node-local state stores only information that changes along the branch-and-bound tree, such as active-column masks and forbidden-entry masks.

## Pseudocode

```text
BranchAndPrice():
    incumbent_value = +infinity
    incumbent_solution = none
    root node:
        E^0 = empty
        E^1 = empty
    open_nodes = {root}

    while open_nodes is not empty:
        select node n from open_nodes by node-selection rule
        remove n from open_nodes

        build initial RMP at node n from parent columns
        add branch constraints theta_e = 0 for e in E_n^0
        add branch constraints theta_e = 1 for e in E_n^1

        run Phase I column generation at node n
        if node n is infeasible:
            prune n
            continue

        run Phase II column generation at node n
        let LB_n be the node LP optimum

        if LB_n >= incumbent_value:
            prune n by bound
            continue

        if theta is integral at node n:
            recover integer solution
            if LB_n < incumbent_value:
                incumbent_value = LB_n
                incumbent_solution = current solution
            prune n
            continue

        choose branching edge e*

        create zero-child n0:
            E_n0^0 = E_n^0 union {e*}
            E_n0^1 = E_n^1

        create one-child n1:
            E_n1^0 = E_n^0
            E_n1^1 = E_n^1 union {e*}

        insert n0 and n1 into open_nodes

    return incumbent_solution
```

## Notes
### Gurobi LP method

- For each phase, **it is very important** to select simplex method (ex. primal simplex, dual simplex) to enhance LP solving time.

### Time-limit output

If the global time limit is reached, output at least:

1. the current incumbent solution,
2. the best lower bound among open nodes,
3. the current global gap,
4. the number of processed nodes,
5. the number of open nodes,
6. prune counts by reason: infeasible, bound, integer,
7. total LP solve time,
8. total pricing time.
